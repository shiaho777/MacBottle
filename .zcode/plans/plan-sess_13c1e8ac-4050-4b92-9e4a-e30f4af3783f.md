## BottleView 重构：管理操作移入 toolbar，主页聚焦运行游戏

### 问题
BottleView 把启动状态、hero、固定程序网格、最近运行、**5 个管理 tile**、底栏全部堆在一个滚动页。管理 tile 列表（104-149 行）是 iOS 设置页风格，占主页最大一块，挤掉了主操作（运行游戏）的视觉权重。底栏的"日志"按钮还和管理区 logs tile 功能重复。

### 改动（单文件：`Whisky/Views/Bottle/BottleView.swift`）

**1. 新增 `.toolbar`（挂在 NavigationStack 上，紧挨现有 `.navigationTitle`）**
一个 `ToolbarItem(placement: .primaryAction)` 的 `Menu`，收纳全部管理操作：
- 已安装程序 → `path.append(BottleStage.programs)`
- 容器配置 → `path.append(BottleStage.config)`
- 运行中的进程 → `path.append(BottleStage.processes)`
- 运行日志 → `path.append(BottleStage.logs)`
- 分隔线
- 导入工作区 → `showWorkspaceImport.toggle()`

Menu label 用 `slider.horizontal.3` 图标 + "管理"。子项复用原 tile 的图标和已本地化的 title key（零新字符串）。

**2. 删除管理区 VStack（103-149 行整段）**
主页只保留：launchStatusBanner → BottleHeroHeader → 固定程序网格 → 最近运行。从 5 段精简到 3 段 + banner，首屏聚焦运行游戏。

**3. 底栏去重复**
删除 `bottleBottomBar` 里的"日志"按钮（330-334 行，和管理 Menu 里的重复）。底栏保留：C盘 / 终端 / Winetricks / 强制停止 / 运行 Menu（主操作）。

### 不动什么
- ContentView 的 toolbar（新建 bottle / 同步 / 刷新 / 引擎徽章）不动。
- 固定程序网格、PinView、最近运行、hero 全不动。
- ProgramsView / ConfigView / 各 destination view 不动（只是入口从 tile 变 Menu）。
- 数据模型、Wine 启动逻辑全不碰。

### 收益
- 主页信息密度均匀：运行游戏（固定网格）是视觉重心，管理操作不抢空间。
- 管理操作收进 toolbar Menu —— macOS 原生工具栏模式，比 iOS 式 tile 列表 native。
- 去掉一个重复入口（日志）。

### 风险与验证
- BottleView 内层 `NavigationStack` 加 `.toolbar`：`.navigationTitle` 已这样挂（合法），toolbar 应落在 detail 列标题栏。**本地构建后启动 app 实际看一眼渲染**（toolbar 项是否正常出现在 BottleView 标题栏、不与 ContentView 的窗口 toolbar 冲突）。若渲染异常，fallback 到把 Menu 放回主页顶部 compact 形式。
- 验证：`swift test` / `swiftlint --strict` / `xcodebuild build` + 手动启动确认 toolbar 视觉。
